# Roadmap (возобновление разработки)

> Срез на 2026-06-30. Разработка возобновлена после паузы. Цель — SaaS на несколько школ (multi-tenant); деплой пока один инстанс.

## Сделано

### Фаза 0 — реанимация окружения
Свежий клон поднят и проверен end-to-end: `npm install`, typecheck, lint, тесты (`npm run test`), `build` — зелёные. Happy-path прокликан под реальным аккаунтом (live-урок, выдача/сдача/проверка ДЗ). Локальный dev смотрит на прод-Supabase (отдельного staging нет).

### Фаза 1 — безопасность сессий
- **CSRF**: глобальный `src/middleware.ts` + `src/lib/server/csrf.ts` (проверка Origin → Sec-Fetch-Site, backstop — SameSite cookie). Покрывает все `/api`-роуты и server-actions.
- **PIN/login lockout**: уже было на уровне БД (RPC `verify_user_pin`: 5 попыток / 15 мин) — изменений не потребовалось.
- **Отзыв сессий (per-user)**: миграция `202606300001_session_revocation.sql` (колонка `user_security.sessions_invalid_before` + RPC `revoke_user_sessions`), enforcement в `resolveAccessPolicy`, авто-отзыв всех сессий при сбросе пароля. Настраиваемый TTL `APP_SESSION_TTL_HOURS` (дефолт 48ч; в проде задан 168ч через Coolify).

## Фаза 2 (текущая) — суженный скоуп

По решению 2026-06-30 в работе только три задачи:

1. **RLS-политики на runtime/контент-таблицах** — изоляция данных между школами на уровне БД (15 таблиц с включённым RLS, но без политик). Самый приоритетный пункт. Используются существующие хелперы `current_teacher_id()` / `current_parent_id()` / `current_student_id()`.
2. **Приглашения в школу с подтверждением по почте** — заменить «молчаливое» мгновенное добавление (демо-заглушка) на pending-invite + письмо + явное принятие.
3. **Родитель видит детей во всех группах** — фикс read-моделей родителя (сейчас читается только первая группа/класс).

### Явно убрано из скоупа (не делаем)
- Admin-UI авторинга контента (методики/уроки/ДЗ остаются через SQL-миграции).
- Транзакции на многошаговых записях.
- Серверный enforce лимита преподавателей в школе.

## Отложено
- Вынос in-memory rate-limit и состояния сессий во внешнее хранилище — не нужно, пока деплой одноинстансный.
- Realtime вместо поллинга для live-урока/чата/нотификаций.
- Кнопка «выйти на всех устройствах» в настройках (механизм `revokeUserSessionsAdmin` уже готов).

## Инфраструктура (важно при деплое)
- Приложение `shidao.ru` + Coolify — на хосте `194.67.122.142` (отдельно от Supabase-сервера `130.49.148.167`).
- DDL на прод-БД применяется через SSH в контейнер `supabase-db` как `supabase_admin` (pooler-роль `postgres` не владелец таблиц).
- При изменении модели БД держать в актуальном состоянии `supabase/schema/current-schema.sql` и `docs/database/current-schema.md` (см. `AGENTS.md`).
